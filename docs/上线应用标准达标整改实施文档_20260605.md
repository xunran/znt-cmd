## 0. 执行原则

```text
1. 先修 P0，再修 P1，再修 P2。
2. 每项必须有：代码改动说明、架构边界说明、单元/集成测试、真实脚本或 E2E 证据。
3. 未通过验证不得进入下一项；若真实环境缺凭据或资源，必须记录为阻塞，不得用 stub 结果替代真实结论。
4. 不用单机结果宣称集群 HA；不用 stub 模型结果宣称真实模型容量。
5. 每项完成后更新本文档状态和报告路径。
```

状态定义：

```text
planned      已纳入计划，未开始
in_progress  正在处理
verified     代码和测试均通过，证据已落盘
blocked      需要外部凭据、真实集群或用户决策
```
