## 0. 定位和边界

本轮先不处理 K8s、集群、多副本、PDB、跨节点调度和跨节点故障转移。单机部署的目标不是“机器宕机也可用”，而是先做到：

```text
单进程 + 单 Postgres 实例 + 本机或单机 Docker/服务管理方式下，
服务入口可保护、依赖异常可摘流、资源可控、长任务不拖垮 HTTP、
迁移可治理、容量有证据、架构后续能继续演进。
```

明确不做：

```text
1. 不做 K8s 多副本、PDB、HPA、Service Mesh。
2. 不做跨机器高可用数据库。
3. 不做分布式队列和跨节点 worker。
4. 不用单机结果宣称集群级 HA。
```

单机上线判定口径：

| 维度 | 单机阶段目标 |
| --- | --- |
| 稳定性 | 依赖异常能快速失败或摘流；HTTP 入口有超时和大小限制；DB 连接可控；迁移不破坏老环境 |
| 性能 | 有可重复 benchmark；有 Postgres-backed 1k/5k/10k run 探针；有 p95/p99 和资源曲线 |
| 扩展性 | `server.go` 不继续膨胀；command/API 测试补齐；单机 worker/limiter/queue 与后续集群化边界清楚 |

## 2. 开发阶段安排

### Phase A：单机入口硬化

目标：先保证单机不会被依赖异常、慢请求、大请求、连接池失控拖垮。

顺序：

```text
S1 -> S2 -> S3 -> S8 -> S12
```

验收：

```text
go test ./...
go test ./... -race -count=1
go vet ./...
scripts/e2e_api_smoke.ps1
scripts/e2e_postgres_release.ps1
新增 readiness/timeout/body-limit/DB-pool 单元和集成测试
```

### Phase B：单机并发和长任务保护

目标：`agent.run` 不再无界占用 HTTP 和 goroutine；达到上限时有明确背压行为。

顺序：

```text
S5 -> S4 -> S12 -> S7
```

验收：

```text
并发超限返回 429/可识别 runtime error，或返回 queued 状态
长任务执行不拖住 HTTP 请求到模型/工具完成
队列长度、等待时间、拒绝数、运行中数量可查询
Postgres-backed 1k/5k/10k 探针有 p50/p95/p99、错误率和资源指标
```

### Phase C：架构收口和测试覆盖

目标：降低继续扩展时的文件膨胀风险，并把 warning 变成可执行任务。

顺序：

```text
S9 -> S10 -> S6 -> S11
```

验收：

```text
scripts/verify_contracts.ps1 warning 归零，或每个 warning 被等价测试证据覆盖
新增 benchmark 可在 CI 或本地稳定输出
server.go 不再承接新增 command 的全部实现
worker/sandbox/managed 在 readiness 或 capability 中明确 production=false/disabled
```

### S4：单机 agent.run 执行模式收口

对应缺口：`dispatchCommand -> Coordinator.HandleEnvelope` 在 HTTP 请求内同步完成 run。

涉及文件：

```text
internal/server/server.go
internal/runtime/kernel/coordinator.go
internal/app/core/core.go
internal/contracts/agent.go
internal/storage/postgres/postgres.go
internal/task/runtime/service.go
internal/server/server_test.go
```

建议分两步：

1. 先加 admission control：同步执行仍可保留，但进入前必须拿到 run slot。
2. 再加单机 worker pool：HTTP 接收后创建 run/task，返回 `queued/running`，后台 worker 调用 Coordinator。

兼容策略：

```text
agent.run 默认仍可同步，增加 payload 或 config 切换：
  execution_mode = sync|async
生产单机默认 async。
测试和本地开发可用 sync。
```

需要新增或明确的契约：

```text
RunStatus queued 或使用 created/running 现有状态表达 queued。
GET /v1/runs/{run_id} 查询状态。
GET /v1/tasks/{task_id} 查询状态。
trace 记录 run.queued、run.started、run.completed/run.failed。
```

测试：

```text
server_test: sync 模式保持旧 agent.run 行为。
server_test: async 模式立即返回 run_id/task_id/status。
server_test: worker 完成后 run/task/trace 可查询。
server_test: worker panic/error 时 run failed，trace/audit 有记录。
```

完成标准：

```text
长模型调用或慢工具调用不会把 HTTP 请求生命周期拉长到不可控。
```
