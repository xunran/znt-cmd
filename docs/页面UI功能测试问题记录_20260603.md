# 页面 UI 功能测试问题记录

测试时间：2026-06-03  
测试对象：`znt--html/ploykit` 前端页面  
测试地址：`http://127.0.0.1:3102` 临时内存运行时  
测试账号：`admin@example.com / Admin@123456`  
测试方式：真实浏览器逐页访问，覆盖公共页、认证页、工作台、模块页、Origin AgentOps、后台管理共 81 个路由。

## 总体结论

当前页面整体更接近“UI 原型 + 部分宿主能力 + 少量真实表单”。公共站点、登录、用户中心、后台管理框架基本能打开；但模块示例页、Origin AgentOps 大量按钮、导入/导出/批量/向导类入口还没有完整功能闭环。多个页面存在“按钮可点击但没有请求、没有跳转、没有提示”的情况。

## 全局问题

### 1. 多处中文显示乱码

严重度：高  
影响页面：Origin AgentOps 部分页面、后台导航部分文案、模块定义中的质量文本、个别公共工具中文文案。  
实际表现：页面中出现类似 `鍏`、`鏅`、`绯`、`妯`、`鐢` 的乱码，而不是正常中文。  
期望结果：所有中文 UI 文案应正常显示。  
备注：这不是浏览器抓取问题，页面真实文本就是乱码，需要检查源文件编码或历史转码问题。

### 2. 主题切换按钮缺少明确反馈

严重度：中  
影响页面：所有带 Header 的页面。  
实际表现：点击 `Theme: System` 只打开菜单或切换状态，页面没有明显当前主题说明；自动巡检点击后未观察到请求、跳转或提示。  
期望结果：打开菜单后能清楚选择 Light/Dark/System，选中后有明确视觉状态。  

### 3. 顶部用户菜单在自动点击时无可见反馈

严重度：中  
影响页面：工作台、后台。  
实际表现：点击 `系统 系统管理员 admin@example.com` 后没有稳定可见反馈，用户菜单不容易确认是否展开。  
期望结果：点击后展示个人资料、通知、退出登录等菜单项，并具备清晰层级和关闭行为。

### 4. 多个“导出 / 导入 / 批量 / 更多 / 筛选规则 / 保存视图”按钮只是占位

严重度：高  
影响页面：Origin AgentOps、后台管理多个页面。  
实际表现：点击后没有请求、没有跳转、没有弹窗、没有 Toast。  
期望结果：至少应弹出上传/导出/筛选面板，或提示“功能开发中”。

## 公共站点页面

### `/zh` 首页

问题：主要是营销展示页，功能入口只有跳转链接，没有实际产品操作。  
实际表现：`开始使用`、`查看文档` 等为链接型入口；页面无产品试用、模块选择、创建工作区等动作。  
建议：如果首页定位为产品入口，应补充明确 CTA 后续流程。

### `/zh/pricing` 价格页

问题：套餐展示没有真实购买/选择闭环。  
实际表现：页面展示 `Starter Pro Monthly`，但公共价格页没有直接完成 checkout 的交互证据。  
期望结果：点击套餐应跳转登录后结账或显示本地结账结果。

### `/zh/contact` 联系页

问题：表单存在，但提交后的可见结果未在页面上明确说明。  
实际表现：表单 action 为 `/api/contact`，字段包含姓名、邮箱、公司、需求；页面文案说“提交后记录请求并邮件处理”，但 UI 未显示提交成功/失败状态说明。  
期望结果：提交后显示成功提示、请求编号或错误提示。

### `/demo` Capability Demo 公共页

问题：页面无模块输出。  
实际表现：页面直接显示 `No module output.`。  
期望结果：至少展示 Demo 的可操作 UI，例如提问、Webhook 示例、任务状态、文件/RAG 能力入口。

### `/public-tools`、`/tools/json`、`/tools/csv`

问题：工具按钮是前端本地处理，不走模块 API。  
实际表现：`JSON / CSV / Text / 格式化 / 压缩` 点击无网络请求；源码中 `PublicToolsWorkbench` 使用 `runLocalTool` 本地处理。  
期望结果：如果产品目标是模块运行时工具，应调用 `/api/modules/public-tools/...` 并展示请求状态、错误、用量记录。

### `/cms-demo`、`/cms`、`/blog`

问题：页面把对象 JSON 直接渲染给用户。  
实际表现：页面出现 `{ "title": "CMS Demo", "loaderData": ... }`，并显示 `MODULE_CAPABILITY_PERMISSION_DENIED`。  
期望结果：应展示文章列表、分类、空态、错误态，不应直接暴露内部 JSON 和权限错误。

### `/shop-demo`、`/shop`、`/store`

问题：页面把对象 JSON 直接渲染给用户。  
实际表现：页面出现 `{ "title": "Shop Demo", "loaderData": ... }`，并显示 `MODULE_CAPABILITY_PERMISSION_DENIED`。  
期望结果：应展示商品列表、购物车/结账入口、库存空态，不应暴露内部 JSON。

## 建议优先级

1. 先修中文乱码，避免所有后续 UI 验收被干扰。
2. 把模块 Demo 页从 JSON/空输出改为正常 UI，至少处理 `capability-demo`、`ai-rag-demo`、`cms-demo`、`shop-demo`。
3. 给所有占位按钮增加“开发中”提示或禁用状态，避免用户误以为功能已可用。
4. Origin AgentOps 先收敛核心链路：新建智能体、运行智能体、查看运行、审批、工具/服务连接。
5. 后台高风险操作增加确认、结果反馈和审计回执。
