## 不可用 / 缺失 / 不满足 UI 的问题

1. **CleanCore 未配置，外部业务链路不可用。**  
   `GET /api/modules/origin-agentops/state` 返回 `MODULE_SERVICE_CONNECTION_MISSING`；创建、运行、同步、健康检查等接口虽然多数返回 2xx，但 `cleanCore.ok=false`，实际写入的是本地降级读模型。UI 上“运行智能体 / 发布 / 工具同步 / 健康检查”会给成功反馈，但不代表真实业务服务已执行。

2. **action 入参错误时没有返回 Origin 业务错误码。**  
   实测 `POST /api/module-actions/origin-agentops/runAgent` 空 body，期望是可读的 `ORIGIN_AGENT_ID_REQUIRED` 一类业务错误；实际返回 HTTP 500，code 为 `MODULE_ACTION_ROUTE_ERROR`。需要把 action handler 的业务错误改成网关允许透出的 envelope，或在路由层映射业务错误码。

3. **Members / Settings 页面没有 Origin 自身 API。**  
   UI 声明有 `members` 和 `settings` section，但 module.ts 没有 `/origin-agentops/members` 或 `/origin-agentops/settings` API；Members 使用本地静态数组，Settings 只是展示 `/state` 的映射状态和外链。如果设计目标是在 Origin 页面内管理成员、角色、邀请、设置保存，这两块属于后端接口缺失。

4. **筛选、分页、导入、批量、导出类 UI 大多没有服务端参数或接口。**  
   现有列表接口基本只返回固定 limit 的全部/近似全部数据，UI 的分页按钮、页码输入、更多筛选、导入智能体、批量操作、导出审计报告等没有对应 API 或 onClick。当前只能算静态 UI 展示，不能满足真实列表管理。

5. **Trace / 审批的高级功能只做了基础 CRUD。**  
   审批创建、批准、拒绝、要求补充信息可以落本地数据；但“审批策略”“批量处理”“审计记录 tab”“查看完整 Trace”“导出证据”“筛选规则”等 UI 没有对应接口。若 UI 设计要求策略管理和证据导出，需要新增接口。

## 审计限制

- Host API 的 POST/PATCH/DELETE 涉及注册、账单、文件、工作区成员、通知、worker、webhook 等写操作，本次未做破坏性全量写入；已做源码枚举和 GET 可达性冒烟。
- Origin AgentOps 的写接口使用 `codex_audit_20260605023903` 前缀创建临时数据，并在结尾执行 cleanup；如果服务使用内存 store，重启后临时数据也会消失。
- CleanCore 未配置时，接口“可用”只代表本地模块读写可用，不代表真实 CleanCore、ToolHost、外部服务可用。
