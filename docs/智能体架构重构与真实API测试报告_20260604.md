# 智能体架构重构与真实 API 测试报告

日期：2026-06-04
范围：对 `docs/智能体技术演进稳定性与解耦边界分析_v0.1.md` 的代码落地核对、重构实施、全路由真实 HTTP 验收和真实模型 smoke。

---

## 1. 结论

本轮结论：

```text
CleanCore 当前架构方向成立，不需要大拆大改。
本轮已把两个影响治理证据和 replay 强度的缺口落到代码：
1. ToolCall 持久化调用时实际 tool_version / execution_profile。
2. Model Runtime 暴露 ModelCapabilityDescriptor，并把能力哈希写入 run snapshot / trace。
```

原架构文档中已澄清的事实偏差：

```text
1. 当前没有独立 handoff DecisionType；内部协作走 tool_call + origin.agent.delegate + AgentHandoff。
2. 当前没有独立 timed_out RunStatus；模型超时以 CodeModelTimeout 进入 failed。
3. ToolCall 治理语义不等于所有字段必须都落在 ToolCall；但为增强 replay，本轮已补 tool_version / execution_profile 快照。
```

架构复查判断：

```text
Runtime Kernel、Decision parser/validator、ToolRuntime、Policy/Approval/Audit、Trace/Replay 的边界仍然合理。
本轮改动没有扩大 hook / executor 的控制权，也没有绕过 ToolRuntime 治理入口。
```

## 5. 架构合理性复查

本轮代码改动符合架构文档中的稳定边界：

```text
1. ToolCall 快照增强了运行事实，不改变工具执行入口。
2. ModelCapabilityDescriptor 增强了模型 adapter 可观测性，不让业务代码依赖 provider 私有 payload。
3. VersionSnapshot 只增加能力 hash，保持 run snapshot 的可比较性。
4. model.called trace 保存可读能力描述，方便 replay / eval / 回归定位。
5. Hook 仍只提供 patch / hint / intent，没有获得执行工具或推进状态的能力。
```

不纳入本轮强改的事项仍然合理：

```text
1. 独立 timed_out 状态需要 API 兼容性决策，当前 CodeModelTimeout -> failed 可表达结果。
2. MCP / A2A adapter 是未来外部 adapter 扩展点，不是当前稳定内核的阻塞缺口。
3. 完整 RuntimeDriver 仍不宜过早开放，否则会稀释 Kernel 的治理职责。
```

## 6. 剩余风险

```text
1. ToolCall 已记录实际 tool_version / execution_profile，但严格 replay 如果要重建完整执行环境，仍需要继续冻结 executor adapter 版本、provider endpoint 版本和外部依赖状态。
2. ModelCapabilityDescriptor 当前覆盖 provider/model/structured output/streaming/openai-compatible/thinking/reasoning/max tokens；未来多模态、内置工具、区域合规、价格和 rate limit 可继续扩展。
3. all-interfaces E2E 在 Windows PowerShell 下主体 passed 后出现过测试宿主进程不自动退出，需要手动停止本地 server；这属于测试脚本清理问题，不影响报告 JSON 的 passed 结果。
4. 工作树中存在大量本轮之前的改动和未跟踪文件，本报告只对本轮架构重构与测试证据负责。
```
